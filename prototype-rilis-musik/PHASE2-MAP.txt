============================================================
FASE 2 — PETA KEBERANGKATAN: STATUS → ENDPOINT → AKSI
============================================================
Peta ini menghubungkan setiap status di prototype V13.0 ke
status & endpoint nyata di main (backend/ FastAPI), beserta
aktor yang berwenang. Daftar endpoint lengkap hasil sapuan:
PHASE2-ENDPOINTS-MAIN.txt (363 endpoint).

Kunci:
  [=]  padanan langsung     [~]  padanan sebagian / perlu peta
  [+]  baru di prototype (belum ada di main → endpoint baru)
  [-]  ada di main, tidak dipakai prototype (dipertahankan)
  [!]  konflik desain yang harus diputuskan sebelum migrasi

------------------------------------------------------------
1. AUTH & AKTIVASI (D7)
------------------------------------------------------------
Status main: label.account_status =
  no_account | active | suspended | blacklisted
  + kyc_status: none | pending_review | verified | rejected
  + mda_accepted_at (timestamp), email_verified

Endpoint main:
  POST /auth/register            label baru (MDA wajib dicentang)
  POST /auth/verify-email        token email → email_verified
  POST /auth/login · /auth/refresh · /auth/logout · /auth/me
  POST /auth/google/id-token     login Google
  POST /auth/google/link         tautkan Google ke akun
  POST /label/logo · POST /label/kyc/ktp   unggah logo & KTP
  GET  /label/kyc                status KYC member
  GET  /admin/kyc · GET /admin/kyc/{label_id}   antrean review
  POST /admin/kyc/{label_id}/action  approve/reject — SUPER saja
       (_kyc_approver → require_super_admin)

Peta prototype → main:
  m.active              [=] account_status==='active'
  m.emailConfirmed      [=] email_verified
  m.contract            [~] mda_accepted_at (prototype menerbitkan
                          dokumen kontrak sendiri → kontrak label
                          tersimpan; main hanya cap waktu MDA)
  m.identity.document   [~] kyc_status==='verified' +
                          kyc_documents.is_current
  m.bank.approved       [~] bank_verifications (admin action)
  application.pending   [~] kyc_status==='pending_review'
  application.correction[+] belum ada status koreksi di main —
                          main pakai rejected + alasan

Celah:
  [!] D7 mengharuskan pembayaran TIDAK menggerbang aktivasi —
      main juga tidak menggerbang; paket diaktifkan terpisah.
      Konsisten.
  [!] Tombol "Cabut Akses" (D7) → POST /admin/labels/{id}/
      revoke-account SUDAH ADA di main — tinggal sambung UI.
  [+] Menu "Pembaruan" & wizard onboarding (langkah, draft
      onboardingDraft105) adalah UI murni — tanpa endpoint.

    ↘ need_revision ↗ (submit ulang)   ↘ rejected
  awaiting_payment (bila PPR belum lunas) · taken_down

Status prototype (status10 + v105):
  draft, submitted, review, revision, clarification, approved,
  delivered, followup, live, partial, partial_closed, closed,
  cancel_requested

Peta prototype → main:
  draft            [=] draft
  submitted        [=] submitted
  review           [=] under_review
  revision         [=] need_revision
  clarification    [+] belum ada — jeda klarifikasi label↔staff
                   perlu status baru atau sub-state
  approved         [=] approved
  delivered        [=] delivered
  followup         [~] tindak lanjut Believe — di main status
                   tetap delivered + tiket/cron menandai;
                   prototype menjadikannya status → putuskan
  live             [=] live
  partial          [+] per-lagu tayang — main menandai di level
                   rilisan; partial perlu status/agregat baru
  partial_closed   [+] idem (rilisan selesai sebagian tayang)
  closed           [~] mendekati rejected/cancelled — bedakan:
                   closed = arsip sukarela label
  cancel_requested [+] permintaan batal — perlu status baru
  (main) awaiting_payment [-] prototype meniadakan gerbang bayar
                   (D7) — endpoint PPR tetap ada untuk PPR
  (main) rejected   [~] prototype: penolakan masuk jalur revision
  (main) taken_down [~] prototype memetakan ke live + penanda
                   (v131-sample mengubah taken_down → live)
